#+TITLE: remoto.el changelog
#+AUTHOR: Ag Ibragimov

Changes to the project, following Keep a Changelog conventions.

* [Unreleased]

** Fixed
- a remoto file no longer opens in the buffer of another remoto file of the same size
- ~copy-file~ from a short name, such as ~/gh:OWNER/REPO/FILE~, copies the file

* [2.6.0] - 2026-10-31

** Added
- adds project.el support: a repository tree is a project - ~C-x p f~, ~C-x p d~, ~C-x p D~, ~C-x p b~, ~C-x p k~, ~C-x p p~
- adds ~remoto-project-find-file~ - ~C-x p R~
- searches in a remoto directory (~C-x p g~, ~consult-ripgrep~, ~grep~, ~find~) stop with a message
- ~project-search~ and ~project-query-replace-regexp~ refuse remoto projects

** Changed
- remoto paths in ~project-list-file~ or ~recentf-list~ no longer load remoto at startup

* [2.5.0] - 2026-10-30

** Added
- adds ~remoto-login~ - log in to a forge with a token, stored in ~auth-sources~
- offers a login when a command needs a token: rate limit, refused token
- the first remoto buffer without a token says GitHub is read anonymously

** Changed
- no git config needed: tokens come from auth-source rows by host
- without a token, remoto reads anonymously from the first request
- rate limit messages say until when
- a 404 without a token suggests ~remoto-login~
- a refused token falls back to the next stored one
- the macOS keychain is read only when nothing else has a token
- ~remoto-reset-auth~ also clears auth-source's cache
- ~remoto-auth-timeout~ is obsolete

** Fixed
- ~remoto-github-auth~ set to ~none~ sends no token
- a network error no longer drops the token for the session

* [2.4.0] - 2026-10-25

** Added
- adds Codeberg - ~/codeberg:~ and ~/cb:~
- adds ~remoto-forgejo-instances~ - other Forgejo and Gitea servers
- one login per forge host; ~C-u M-x remoto-reset-auth~ forgets one
- adds ~%k~, the ref kind, to ~remoto-forge-url-templates~
- adds ~remoto-unregister-forge~

** Changed
- requires ~ghub~ 5.3.0
- refs with a slash work: ~/github:o/r@release/2026.5.0:/~
- topic buffers are named by path: ~*remoto: /github:OWNER/REPO#N*~
- forges plug in through a contract: ~remoto-register-forge~
- caches are per forge
- a refused token switches its forge to anonymous until ~remoto-reset-auth~
- owner completion sends one search per keystroke, not up to four

** Fixed
- slow answers with a token no longer fall back to anonymous
- ~/codeberg:~ completion works before the ~/codeberg:~ listing is opened
- upgrading from 2.3.0 in a running session works
- Codeberg pages load in parallel
- fewer requests for a Codeberg account's repositories
- ~remoto-browse~ says it reads GitHub names only
- API errors name the host and the status
- topic completion under Vertico no longer errors
- GitHub URLs with slashed refs or query strings open the right place
- multi-line Forgejo descriptions stay on one line
- commit annotations work in subdirectories
- Embark actions work without Vertico's directory tidying
- your Codeberg listing shows only your own repositories
- an empty repository opens as an empty directory

* [2.3.0] - 2026-10-20

** Added
- Dired lists accounts at ~/github:~ and repositories at ~/github:OWNER/~
- adds ~remoto-listing-cap~ - repositories per listing, 1000
- ~remoto-refresh~ refetches a listing
- a name with no exact match opens a Dired of matches: accounts, repositories, refs, files
- Embark actions on listing lines and on branch and tag lines
- adds ~make test-e2e~

** Changed
- ~..~ at a repository root goes up to the owner listing
- ~/github:NAME~ without a slash lists matching accounts

** Fixed
- ~/github:OWNER/..~ no longer asks GitHub for a repository named ~..~
- the Dired of ~/github:~ names its entries right
- Embark no longer takes ~.~ for a file
- a subdirectory Dired shows no stray ~wildcard~ line

* [2.2.0] - 2026-10-19

** Added
- Evil's ex commands open remoto paths: ~:e~, ~:sp~, ~:vs~

* [2.1.1] - 2026-10-16

** Fixed
- Dired reads names under ~-F~ (~--classify~)
- symlinks no longer break a listing
- ~RET~ on ~.~ and ~..~ works
- file operations on remoto names keep the caller's match data

* [2.1.0] - 2026-10-04

** Added
- adds ~remoto-inhibited-functions~ - keeps lsp-mode and Eglot out of remoto buffers

* [2.0.0] - 2026-09-13

** Changed
- loading remoto changes nothing: ~global-remoto-mode~ installs everything and turns on at first use
- the fetch indicator is a ~⟳~ before the input, for every request
- ~remoto-unload-function~ turns the mode off
- a broken auth-source backend is reported once
- Embark swallows only remoto's lookup errors

** Fixed
- HTTP errors read clearly: not found, rate limit, auth
- ~dired~ on a short path opens the repository
- ~/gh:~ paths from Lisp work like ~/github:~ ones
- a missing file opens an empty buffer, as with TRAMP
- the ~.git~ URL from GitHub's Code button parses
- the first call after a failed auth lookup goes anonymous
- URLs percent-encode special characters
- issue and pull request candidates keep remoto's order
- binary files, images included, open as binary
- typing during completion leaves no ~*http*~ buffers behind
- pull request and issue URLs open the topic
- Embark on a ref root offers repository actions
- the first ~find-file~ of a session on a short path works
- ~recentf~ keeps remoto paths
- ~@~ completion no longer fetches a tree per ref
- the fetch indicator stays when the prompt is cleared
- tokens no longer show in ~remoto--pending-requests~
- ~check-declare~ is clean
- the README names ~remoto-copy-url~

* [1.9.1] - 2026-09-09

** Changed

* [1.9.0] - 2026-09-04

** Fixed
