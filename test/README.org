Run =make deps= once: it installs the packages of every profile into =.elpa=.

* The cases

=test/remoto-e2e-cases.el= holds what a person types and the completion profiles.  The replay suite runs six: vanilla, fido, vertico, orderless, evil, embark.  The terminal runs add three that have no golden files: ido, evil-vertico (evil with vertico and orderless) and full (evil, vertico, orderless, marginalia, consult, embark).  The Codeberg names run in the terminal only, since no recorded answers replay them.  =REMOTO_E2E_ONLY=, a regexp matched against the case name with letter case counting, runs some of the cases.

Where a case ends in a Dired or an Embark Collect or Export buffer, both suites check its lines: its header and its entries only, one line each, with no control character or raw byte.  The replay suite keeps what it finds, and the names the buffer lists, in its states, so =make test-e2e=, and CI with it, fails on a broken line.

* make test-keys

Each profile is an =emacs -nw -q= with remoto installed by package.el from a tar of the checkout, under a private tmux server.  Everything lives in =.keys/PROFILE/=.  No window opens and nothing takes focus, on macOS or Linux.

The answers come from the real forges, so no golden file holds them.  Read the results, or compare them with origin/main:

#+begin_src sh
make test-keys-vertico                                    # one profile
make -j9 test-keys                                        # all nine side by side; they share GitHub's rate limits
REMOTO_KEYS_MAIN=1 make test-keys-vanilla                 # origin/main's remoto too, with a DIFF wherever the two end apart
REMOTO_E2E_TOKEN=$(gh auth token) make test-keys-vanilla  # signed in to GitHub
REMOTO_E2E_ONLY='^ff /gh:agzam' make test-keys-vanilla    # some cases
#+end_src

- Each case prints one line: profile, case, seconds, then ~BUFFER | DIRECTORY, FILE or MODE | n=NAMES | calls=REQUESTS | MESSAGES~.  The whole states go to =.keys/PROFILE/results/=.
- Seven fixed checks hold whatever the forge's data, and each failure prints a =FAIL= line and makes the run exit 1: a case ends where the replay of it ends, Dired or file (a profile without golden files takes vanilla's, and evil's for ex cases; ido takes its own landing where its =C-j= ends a case elsewhere, as on origin/main, and =RET= on an account line of =/github:= opens the token's own account); the typed name is the first line of a Dired of matches; the lines of a Dired or an Embark Collect or Export buffer are its header and its entries, with no control character or raw byte, and Embark's annotations start at one column; no message holds raw HTTP text; a case makes at most 20 distinct requests, and at most 20 commit annotations per directory besides, which remoto asks one per file of the directory it lists; a web URL the case copies or opens in a browser loads, with a status below 400, as curl asks it (Codeberg answers other clients a bot check, 200 for any path); an Embark =y= case copies a URL and a =b= case opens one.  Since pending input cancels remoto's fetch, the runner waits for Emacs to go idle after a submit that more keys follow and before an Embark key.  A case still busy after 60 s fails too.  The replay suite records the same buffer problems in its states, minus the columns, which batch Emacs cannot see.
- A case whose Emacs gives no state, say one stuck in a host lookup, fails with the reason, and that Emacs gets a minute to answer before a restart.  An Emacs that cannot start stops its profile with a =FAIL ... stopped:= line.  The results so far are written either way, and the run exits 1, never 255, and leaves no tmux server behind.
- The runner asks the forges itself through curl, never url.el: a batch Emacs exits on an error in a process sentinel.  Without curl the run says once that it checks no web URL and asks no forge anything.
- The embark and full profiles also collect (=C-c c=) and export (=C-c e=) the candidates of annotated prompts: an owner's repositories, the topics of a repository, a directory's files; on Codeberg, technomancy's repositories, one of whose descriptions spans lines.  They run Embark's actions on Codeberg's targets too, as the replay suite does on GitHub's.
- ~REMOTO_KEYS_INIT=FORM~ has each profile evaluate FORM at the end of its init, say to plant a regression and see a check fail: ~REMOTO_KEYS_INIT='(with-eval-after-load (quote remoto) (fset (quote remoto--one-line) (function identity)))'~.
- With =REMOTO_KEYS_MAIN=, the Codeberg cases run on the checkout only: origin/main has no Codeberg.
- Each profile has a git config and an auth-source of its own, empty unless a scenario fills them, so nothing of yours reaches it but the token you pass.  The token reaches it through a file only you can read, which the profile deletes on start.  The run asks GitHub whose token it is and puts that account in the profile's git config as =github.user=, since ghub uses no token without one.  It asks up to three times; when no answer names an account, the run says why and exits 1 rather than read anonymously.  Without a token remoto reads anonymously.
- The run waits whenever GitHub has fewer than 8 searches left.
- ~REMOTO_KEYS_SIZE=COLSxLINES~ sets the terminal, 100x40 by default.

* make test-keys-scenarios

Each scenario is a profile, vanilla unless it names another, with a git config, an auth-source and an init of its own, in =.keys/scenarios/=.  Its cases print the lines and run the checks of =make test-keys=; its probes print lines of their own, such as =logins=, =auth= (per host: requests, those with a token, those with GitHub's token) and =forges=; its checks print a =PASS= or =FAIL= line each, and a =FAIL= makes the run exit 1.

| Scenario    | Setup                                                              | What it shows                                                                                                                                                                       |
|-------------+--------------------------------------------------------------------+-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| =none=      | no account name, no token                                          | anonymous reads, no password prompt, no token sent                                                                                                                                  |
| =cbbad=     | =forgejo.user= and a Codeberg token that Codeberg refuses          | the fallback to anonymous reads, then =C-u M-x remoto-reset-auth=                                                                                                                   |
| =lit=       | GitHub's token in =remoto-github-auth=, needs =REMOTO_E2E_TOKEN=   | GitHub's token never goes to Codeberg or gitea.com                                                                                                                                  |
| =cbtoken=   | a Codeberg token in auth-source, needs =REMOTO_E2E_CODEBERG_TOKEN= | =/cb:= lists your account and organizations, your repositories list, an organization of yours and a private repository open when the run finds them, the token never goes to GitHub |
| =boot-...=  | a fresh Emacs for each of six paths, three per forge               | the first operation of a session loads remoto through its autoload, and which features and handlers it leaves                                                                       |
| =mock=      | a Forgejo instance in the runner, answering 429, 503, 502, 500     | the message of each fault, then the repository once it relays Codeberg                                                                                                              |
| =instances= | =remoto-forgejo-instances= set at run time with =M-:=              | gitea.com, refused prefixes and hosts, removal, two hosts with one topic                                                                                                            |

The login scenarios play a new user: each gets a HOME of its own under =/tmp=, so Emacs's default =auth-sources= find nothing of yours and =remoto-login= writes only there, and a =~/.gnupg= whose pinentry opens no window.  The token is pasted through tmux, as a terminal pastes it.

| Scenario                                                    | Setup                                                                                     | What it shows                                                                                      |
|-------------------------------------------------------------+-------------------------------------------------------------------------------------------+----------------------------------------------------------------------------------------------------|
| =first-PROFILE=                                             | no token, no git config; vanilla, evil and full                                           | public repositories open, the hint once, "not found or private", =/gh:= asks to log in             |
| =store-...=                                                 | no =~/.authinfo.gpg=, with loopback, no gpg, read-only, no browser, symmetric, plain only | where the token goes, what is asked on the way, the other rows kept, mode 600                      |
| =mistyped=, =revoked=                                       | a token GitHub refuses, typed or stored                                                   | the message or the question to log in again, then the new row in place of the old                  |
| =option-stale=                                              | a refused token in =remoto-github-auth=                                                   | the stored login in the next session                                                               |
| =existing-...=, =accounts=                                  | ghub's, Forge's and netrc rows, two accounts, no git config                               | the token found and sent, no hint and no question                                                  |
| =codeberg-login=                                            | no Codeberg token                                                                         | =/cb:= asks, the permissions named, the account listed, nothing sent to GitHub                     |
| =dired-ret=, =option-none=, =entry-points=, =login-PROFILE= | GitHub's limit for reads without a token run out, every profile                           | when remoto asks to log in and when it never does, =y=, =n= and =C-g=, the login, the next session |

The last row spends what is left of GitHub's hourly requests without a token for your IP, so those scenarios run only by name; anything else of yours that reads GitHub without a token fails until the reset the run prints.

#+begin_src sh
make test-keys-scenarios                                    # all; lit and cbtoken skip without their tokens
REMOTO_KEYS_SCENARIOS='none mock' make test-keys-scenarios  # some
REMOTO_E2E_CODEBERG_TOKEN=TOKEN REMOTO_KEYS_SCENARIOS=cbtoken make test-keys-scenarios
REMOTO_E2E_TOKEN=$(gh auth token) REMOTO_KEYS_SCENARIOS='login-vanilla login-evil' make test-keys-scenarios
#+end_src

The Codeberg token needs read access to repositories, issues, organizations and your user; the run asks Codeberg for its account, and stops with exit 1 when Codeberg names none.  It goes into =.keys/scenarios/fixtures/sc-cbtoken.authinfo=, readable by you only, which the run deletes when the scenario ends; with =REMOTO_KEYS_KEEP= it stays until =make clean=.

** Watching and exploring by hand

Watch a profile while it runs, without disturbing it:

#+begin_src sh
tmux -S .keys/vertico/tmux.sock attach -r -f ignore-size -t =rk-vertico
#+end_src

~REMOTO_KEYS_KEEP=1~ leaves the profiles running after the cases; the run prints how to reach them:

#+begin_src sh
tmux -S .keys/vertico/tmux.sock attach -t =rk-vertico                  # type into it yourself
tmux -S .keys/vertico/tmux.sock send-keys -t =rk-vertico: C-x C-f       # or send keys by name
tmux -S .keys/vertico/tmux.sock send-keys -t =rk-vertico: -l -- /gh:agzam/
emacsclient -s .keys/vertico/sock/vertico --eval '(remoto-keys-line)'   # where it ended, in one line
emacsclient -s .keys/vertico/sock/vertico --eval '(remoto-keys-state)'  # and in full
tmux -S .keys/vertico/tmux.sock kill-server                            # stop
#+end_src

* make test-keys-live

Types the =C-x C-f= and =C-x d= cases into the Emacs you work in, through its server (=M-x server-start=; =REMOTO_KEYS_SERVER= names another one).  It tests remoto in your configuration, so results differ from person to person.  It tests the remoto your Emacs has loaded: reload it after a change.

Keep off the keyboard while it runs: what you type joins the case.  The cases run in a =*remoto-keys*= buffer.  At the end the run puts back your windows, the minibuffer histories, =recentf-list= and =save-place-alist=, removes its advice, and kills only the buffers the cases opened.  It runs no checks and exits 0: your configuration decides where a case ends.  When your Emacs stops answering, the run puts it back as far as it can, writes the results so far, says why and exits 1.

* Looking further

The targets above check mechanically.  A person, or an agent with a shell, looks further:

1. Run a profile with ~REMOTO_KEYS_MAIN=1~ and read each DIFF: a fix, a regression, or GitHub's data that changed in between.
2. Keep a profile with ~REMOTO_KEYS_KEEP=1~ and try what the cases miss: the feature under review, odd names, a slow network, a second forge.
3. Run =make test-keys-live= to see the change in a real configuration.
4. Turn each confirmed regression into a case in =test/remoto-e2e-cases.el=, record its answers with =make test-e2e-record=, and the replay suite catches it from then on.
